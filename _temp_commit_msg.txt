fix(conn): 单端口默认部署 /ws 被白名单拒 + auth 阶段不可见标题撑出滚动条

两处用户可见缺陷，都已复现并定位到根因：

1) 单端口默认部署下 /ws 一律 403
   单端口是 README 与 go run ./cmd 的默认形态（PR_ADDR 默认 127.0.0.1:8080、
   PR_SERVE_STATIC 默认 true），但 PR_ALLOWED_ORIGINS 默认只列 Vite 5173。
   S-5 删掉同源隐式放行后，页面 Origin http://127.0.0.1:8080 不在白名单，
   症状是「页面能打开、房间永远连不上」。这是默认值自相矛盾，不是使用者的配置错误。
   默认值补上 8080 两种写法；回环地址是显式枚举的常量、与请求头无关，
   不削弱 S-5（新增负向判据钉住非白名单仍 403）。

2) auth 阶段登录窗把整页撑出滚动条
   标题在 auth 阶段 opacity:0 + scale(0.4)，但两者都不影响布局占位 ——
   仍实占 132px。内容总高 733px，视口低于约 733px 即出现整页滚动条，
   而滚动的那一段全是看不见的东西。改为 auth 阶段把它移出布局流。

3) 账号能力关闭时前端不再显示裸「请求失败（HTTP 404）」
   /api/auth/* 未注册是该形态的设计行为（有测试钉住），但界面上那句话
   看起来像整个后端挂了。改为如实说明「未启用账号能力（游客模式）」并指出
   仍然可用的路径（有房间码即可进房）。

验证：go test ./... 全绿；前端构建门槛通过（window.__pr=0、innerHTML=0、
v-html 仅 MarkdownView）；新增 TestWSOriginDefaultCoversBothLocalEntries。
真机验证（headless Chrome + 生产构建）：登录窗 7 个视口高度均无滚动条且未被裁切、
hero 态标题仍在布局流、收起登录窗后标题正确回到布局流、Origin 白名单 7 判据全过。
